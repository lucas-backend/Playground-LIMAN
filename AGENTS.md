## LIMEN Documentation Rules

- Project name: LIMEN (Sistem Absensi Terintegrasi).
- Existing frontend implementation is the source of truth
  for the current project state.
- Planned backend stack: Go and PostgreSQL.
- UI/UX designs are references, not proof of confirmed
  business requirements.
- Distinguish verified facts, proposals, assumptions,
  and open decisions.
- Never invent business rules, roles, API endpoints,
  database entities, or application features.
- During the documentation phase, do not modify application
  source code, dependencies, or build configuration.
- Do not overwrite existing project files.
- Keep all approved project documentation in docs/.
- Maintain consistent requirement IDs, API contracts,
  architectural decisions, and acceptance criteria.
- Do not claim tests or validations were run unless
  they were actually executed.
